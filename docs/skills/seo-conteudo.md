# Skill — SEO e Conteúdo Papirar

## Objetivo

Planejar crescimento orgânico do Papirar usando páginas públicas, questões, concursos, cursos e dados reais de aquisição/comportamento. A Skill deve transformar o acervo da plataforma em conteúdo encontrável no Google e útil para candidatos, sem criar páginas artificiais, conteúdo duplicado ou promessas sem evidência.

## Princípio central

SEO do Papirar deve nascer do próprio produto:

**concurso → disciplina → tópico → dúvida/intenção de busca → questão → explicação → curso/estudo**.

A prioridade não é publicar o maior número possível de páginas. É criar e fortalecer páginas que respondam a intenções reais e conduzam o usuário para estudo relevante.

### Catálogo e conteúdo Papirar

Usar ferramentas de leitura para confirmar:

- corporações;
- concursos/provas;
- disciplinas;
- tópicos;
- materiais-fonte;
- cursos;
- cobertura dos cursos;
- questões publicadas.

Nunca recomendar uma página como autoridade sobre um tema que o Papirar praticamente não cobre sem explicitar a lacuna.

## Intenções de busca prioritárias

Classificar oportunidades em grupos.

### 1. Concurso

Exemplos de intenção:

- questões SD PMERJ;
- questões CHOAE CBMERJ;
- simulado de determinado concurso;
- matérias cobradas;
- como estudar para determinado concurso.

### 2. Disciplina e tópico

Exemplos:

- questões de Direito Constitucional para PMERJ;
- questões de APH CBMERJ;
- questões sobre Estatuto do CBMERJ;
- exercícios sobre determinado tópico do edital.

### 3. Questão específica

Páginas públicas de questões podem capturar buscas long-tail quando possuem:

- enunciado indexável;
- alternativas adequadas;
- resposta correta;
- comentário didático original;
- contexto de disciplina/tópico/concurso quando aplicável.

### 4. Conteúdo educativo evergreen

Guias e páginas úteis que continuam relevantes mesmo fora do pico de um edital.

Exemplos:

- como estudar por questões;
- como montar caderno de erros;
- como revisar questões erradas;
- como usar simulados na preparação.

## Fluxo de auditoria SEO

### 1. Definir objetivo e escopo

Determinar se a análise é:

- geral;
- de um concurso;
- de um curso;
- de uma disciplina;
- de uma landing page;
- de páginas públicas de questões.

### 2. Verificar demanda observada

Consultar aquisição, landing pages e eventos quando disponíveis.

Identificar páginas que já recebem tráfego orgânico e páginas estratégicas com pouca exposição.

Baixo tráfego sozinho não prova problema técnico de SEO.

### 3. Confirmar oferta e cobertura

Antes de priorizar uma palavra-chave ou cluster, verificar se o Papirar possui conteúdo suficiente relacionado.

Classificar a cobertura como, por exemplo:

- forte;
- suficiente;
- limitada;
- inexistente.

A classificação deve ser baseada nos dados disponíveis, não inventada.

### 4. Mapear intenção para página

Evitar criar várias URLs para a mesma intenção.

Preferir uma página principal forte para cada intenção relevante e páginas complementares quando houver diferença real de objetivo de busca.

### 5. Identificar oportunidades internas

Procurar ligações naturais entre:

- questão → tópico;
- tópico → disciplina;
- disciplina → concurso;
- questão → curso;
- concurso → curso;
- conteúdo educativo → recurso do Papirar.

Links internos devem ajudar navegação e contexto; não devem ser inseridos mecanicamente apenas para SEO.

## Estratégia para páginas públicas de questões

As questões são um ativo central de SEO do Papirar.

Priorizar questões que:

- estejam publicadas;
- tenham enunciado completo e legível;
- tenham comentário didático original;
- estejam corretamente classificadas;
- estejam relacionadas a concursos e tópicos relevantes;
- não sejam duplicadas.

Uma questão com comentário fraco ou classificação errada não deve ser promovida como página estratégica até ser revisada.

Quando encontrar problemas editoriais, encaminhar para a Skill Revisor/Auditoria em vez de alterar conteúdo silenciosamente.

## Clusters de conteúdo

Quando houver cobertura suficiente, organizar conteúdo em clusters.

Exemplo conceitual:

**SD PMERJ**

→ página principal do concurso

→ disciplinas do edital

→ tópicos relevantes

→ questões públicas comentadas

→ simulados/recursos de estudo

→ curso correspondente

O mesmo modelo pode ser aplicado a CBMERJ e outros concursos sem criar páginas vazias apenas para preencher a estrutura.

## Priorização de oportunidades

Ordenar oportunidades considerando:

1. relevância para cursos e concursos ativos;
2. intenção de busca compatível com o produto;
3. cobertura de conteúdo existente;
4. sinais de tráfego/demanda quando disponíveis;
5. proximidade da conversão;
6. esforço para produzir ou melhorar a página.

Uma palavra-chave aparentemente popular não deve receber prioridade automática se não tiver relação clara com o público e a oferta do Papirar.

## Conteúdo editorial

Ao propor conteúdo, informar:

- intenção de busca;
- público;
- página-alvo;
- título sugerido;
- abordagem do conteúdo;
- CTA apropriado;
- recursos internos que podem ser ligados;
- métrica de avaliação.

Evitar conteúdo genérico produzido apenas para preencher calendário.

## Títulos e snippets

Títulos devem:

- corresponder ao conteúdo real da página;
- colocar o assunto principal de forma natural;
- diferenciar páginas semelhantes;
- evitar clickbait enganoso.

Descrições devem explicar valor e contexto sem prometer posição no Google ou aprovação em concurso.

## Conteúdo duplicado e canibalização

Antes de recomendar nova página:

- verificar se já existe página equivalente;
- considerar melhorar a página existente;
- evitar múltiplas páginas competindo pela mesma intenção;
- evitar publicar variações mínimas apenas trocando o nome do concurso.

Quando houver páginas semelhantes, recomendar consolidação apenas como estratégia. Qualquer alteração estrutural/destrutiva deve seguir confirmação e ferramenta apropriada.

## SEO técnico

Quando a pergunta envolver sitemap, robots, canonical, indexação, status HTTP, structured data, performance ou HTML real, a Skill deve distinguir:

- evidência observada no repositório/site;
- hipótese técnica;
- recomendação.

Não declarar que uma página está indexada apenas porque está no sitemap.

Quando necessário, usar pesquisa pública/web para verificar comportamento externo atual, sem substituir dados do Search Console quando estes forem necessários.

## Search Console

Se uma integração do Search Console estiver disponível no futuro, priorizar:

- consultas;
- páginas;
- impressões;
- cliques;
- CTR;
- posição média;
- cobertura/indexação quando disponível.

Até existir ferramenta conectada, não inventar dados do Search Console nem tratá-los como equivalentes aos dados do GA4.

## Conversão orgânica

SEO não termina no clique.

Ao avaliar uma página orgânica, considerar a sequência:

**impressão → clique → página → interação → cadastro → trial → pagamento**.

Usar dados internos e GA4 para aproximar essa análise quando possível, deixando claro quando não existe atribuição suficiente para ligar uma venda a uma página específica.

## Segurança

Esta Skill é principalmente analítica e editorial.

Não deve automaticamente:

- excluir páginas;
- desativar cursos;
- alterar taxonomia em massa;
- fundir tópicos;
- arquivar questões;
- mudar preço;
- publicar alterações estruturais.

Operações destrutivas, estruturais ou em lote exigem confirmação explícita quando forem executadas pelas ferramentas responsáveis.

A saída deve levar a uma fila priorizada de trabalho:

**intenção → oportunidade → conteúdo disponível → página correta → ação recomendada → CTA → métrica de sucesso**.

A Skill deve privilegiar qualidade, relevância e integração com o produto em vez de volume artificial de páginas.
